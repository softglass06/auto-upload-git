# Git 新手助手

一个 Windows 傻瓜式 Git 工具:双击图标打开一个**中文菜单**,上传项目、更新、查看改动、拉取更新都在里面点选完成,不需要记任何 git 命令。

## 功能

双击 `upload.exe` 打开中文菜单:

- **[1] 上传新项目** — 第一次把一个项目传到 GitHub。自动识别三种情况:
  - 文件夹自带 `.git` → 原地提交并推送
  - 没有 `.git` → 选择「新建独立仓库」或「复制进某个已有仓库」
- **[2] 更新项目** — 项目有改动,一键推上去(自动过滤测试/构建文件)
- **[3] 查看改动** — 看看哪些文件变了、最近提交了什么
- **[4] 拉取更新** — 把远程的最新改动下载下来
- **[5] 配置** — 打开『我的项目列表』和『过滤规则』两个文件,想改就改
- **[6] 克隆项目** — 把队友的仓库克隆到本地,加入小组协作
- **[7] 分支管理** — 新建 / 切换 / 合并分支(协作时每人开自己的线)

拖拽也可以:把文件夹直接拖到 `upload.exe` 图标上,自动进入「上传」流程。

### 其它贴心点

- **双重过滤**:`filter-rules.txt` 的默认规则 + 项目自己的 `.gitignore`(原地提交靠 git 识别;复制模式也会读源文件夹的 `.gitignore`,暂不支持 `!` 取反)
- **只过滤新增文件**:过滤规则只作用于「还没被 git 追踪的新文件」;已经追踪的文件改动/删除一律照常提交
- **中文描述 → 规范提交**:打一句中文,用 Claude 润色成简洁的提交信息(没装 Claude 就退回原文)
- **引导建仓**:仓库没关联远程时,给出中文分步提示,去 GitHub 建好空仓库后把地址粘回来即可
- **基础 .gitignore**:新建仓库时自动生成,忽略 `node_modules` 等常见文件
- **先预览后提交**:提交前先列出会传哪些、跳过哪些,确认才动手

## 小组协作(多人一起改)

多人一起做一个项目时,别都往 `main` 上直接推,容易互相覆盖。正确姿势是每人开自己的分支,改完再合并。工具里分三步走:

1. **把队友的仓库拿下来** —— 菜单 `[6] 克隆项目`,粘贴队友发的仓库网址,选个文件夹,工具会自动 clone 并加进项目列表。
2. **开自己的分支干活** —— 菜单 `[7] 分支管理` → `新建分支`,起个名字(建议 `你的名字-功能`,比如 `xiaowang-登录`)。之后用 `[2] 更新项目`,改动就只推到这条分支上,不影响别人的 `main`。
3. **合并回 main** —— 推上去后,去 GitHub 网页点「Compare & pull request」请队友合并;或者在自己的电脑上用 `[7] 分支管理` → `合并分支` 把分支并回 `main`。

分支管理里还能 `切换分支`(在几条线之间来回换)、`合并分支`(把别的分支并进当前分支);合并遇到冲突时会像拉取一样给「撤销 / 手动处理」两个选择。

## 安装

1. 下载本仓库 zip 并**解压全部**(或 clone)到本地
2. 双击 `upload.exe` 打开中文菜单;也可以把文件夹拖到它上面直接上传
3. 建议右键 `upload.exe` →「发送到」→「桌面快捷方式」,重命名为「Git 助手」,以后双击桌面图标就行

> 首次双击 `upload.exe` 时,Windows 可能弹「Windows 已保护你的电脑」,
> 点「更多信息」→「仍要运行」即可(只弹一次,因为这是没签名的小工具)。

> 为什么打包成 exe? 因为直接在 zip 里双击 `upload.cmd` 时,Windows 只解压那一个
> 文件、旁边的脚本没跟上会报错;单个 exe 把所有东西都装进去了,双击即用,不再
> 受「解压 / 编码 / 换行」影响。

## 依赖

- **Windows**(PowerShell 5.1 或更高)
- **git**,且在 PATH 中(没装会弹出中文安装引导)
- **Claude Code CLI**(可选,用于润色提交信息;没装会退回用你输入的原文)

## 配置

### repos.txt(我的项目列表)

每行一个,格式 `名字|完整路径`,`#` 开头是注释:

```
我的网站|D:\code\my-website
小白爬虫|D:\codework\green-hand-bug
```

上传新项目后,按提示可以自动加进这个列表,之后「更新 / 查看 / 拉取」就能直接选它。

这个文件已被 `.gitignore` 忽略,不会随工具上传,里面的个人路径不会泄露。

> 从这一版开始,`repos.txt` 和 `filter-rules.txt` 统一存在 `%APPDATA%\auto-upload-git\`
> (例如 `C:\Users\你\AppData\Roaming\auto-upload-git\`),不再和程序放在一起。
> 这样不管程序放在哪、是不是从 zip 临时目录里双击,你的列表都不会丢。旧版数据会在首次运行时自动搬过去。

### filter-rules.txt(过滤规则)

- `#` 开头是注释
- 目录名后加 `/` 表示整个目录跳过,例如 `node_modules/`
- 带 `*` 或 `?` 的通配符匹配文件名 / 目录名,例如 `*.test.*`
- 不带斜杠的普通名字匹配任何一层的同名目录或文件,例如 `__pycache__`
- 默认已包含 `.env`、`*.key`、`*.pem` 等密钥文件,防止把密码/密钥传上去

## 常见问题

- **为什么之前脚本全英文?** 老版本为了避开 PowerShell 5.1 的 GBK 编码坑,刻意只用 ASCII。现在 `upload.ps1` 已存为 **UTF-8 带 BOM**,中文能正确显示。**注意:请不要用编辑器把它另存为无 BOM 的编码**,否则中文会乱码或吞行。
- **下载 zip 后双击报「'5001' 不是内部或外部命令」?** 那是 `upload.cmd` 里的中文 + LF 换行被 cmd.exe 拆坏(比如把 `chcp 65001` 拆成 `chcp 6` + `5001`)。现在 `upload.cmd` 已改为纯 ASCII 标题(中文标题由 `upload.ps1` 设置)并用 CRLF 换行保存。**注意:不要往 `upload.cmd` 里加中文**,中文一律写在 `upload.ps1` 里。
- **想跳过 Claude 润色?** 不装 Claude Code CLI 即可,脚本会自动退回用你输入的原文。
- **推送失败提示「远程仓库不是空的」?** 说明建仓库时勾了 README 等选项。去 GitHub 删掉该仓库,重新建一个空的(三个复选框都不勾)再试。
- **`repos.txt` 会泄露我的路径吗?** 不会。这个文件已被 `.gitignore` 忽略,不会被提交上传。
- **第一次提交提示我设置名字/邮箱?** 是的,全新电脑上 git 没配置过身份,提交会失败。工具会在第一次使用时引导你输入一次,以后就不用再设。
- **推送时弹出浏览器或要密码?** 首次推送 GitHub 会要求登录,浏览器会自动弹出;如果出现「Username / Password」,去 GitHub → Settings → Developer settings → Personal access tokens 生成一个 Token,当密码粘贴即可(不要再填账号密码,GitHub 已停用)。
- **推上去了,但 GitHub 页面看着还是空的?** 可能是默认分支对不上。点仓库左上角的分支下拉,把默认分支设成 `main`(或你推送的那个分支名)即可。
- **`.env`、密钥文件会被传上去吗?** 不会。默认过滤规则已经挡住 `.env`、`*.key`、`*.pem`、`id_rsa*` 等,避免把密码/密钥传上 GitHub。
- **拉取时提示「冲突」?** 说明你和别人改了同一处。工具会给你两个选择:输入 `a` 撤销这次拉取恢复原样(推荐),或输入 `k` 自己打开冲突文件手动合并。
